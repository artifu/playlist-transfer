Large playlist guide · 8 minute read

Transfer a large playlist without turning review into guesswork.

The safest strategy depends on whether you are testing the catalog, validating the workflow, or creating the final destination playlist.

Written and maintained by the PlaylistXfer project · August 2, 2026

Current production boundary

The web flow analyzes up to 500 rows in one transfer. Full playlist selects that production maximum. The 150- and 50-track options are faster dry runs, and only rows included in the chosen analysis can be created from that report.

Use a small mode when you want to learn whether the link is readable, the Apple Music storefront is correct, and the match report behaves as expected. Start a new Full playlist analysis when you are ready to create the actual destination.

Do not analyze 50 rows, approve them, and assume the remaining hundreds will be added later by the same report. PlaylistXfer creates from the analyzed rows it can show and explain.

Prepare the source before spending time on matching

Open the Spotify playlist in a private browser window. If the title and tracks are not visible while signed out, the anonymous public-link flow may fail before playlist size matters. Copy a fresh Share → Copy link to playlist URL rather than reusing a personalized redirect.

Scan the source for item types that are likely to stay out:

  • Local files cannot become Apple Music catalog songs automatically.
  • Podcasts and episodes are outside the music-playlist creation flow.
  • Unavailable or removed tracks may appear in the Spotify count without usable public metadata.
  • Very repetitive playlists can contain intentional duplicate rows that should not be deduplicated blindly.
  • Version-heavy collections need extra review for live, remix, remaster, acoustic, clean, and explicit editions.

If you own the playlist and want a cleaner transfer, make a copy before editing. Removing untransferable rows from a working copy can simplify comparison while preserving the original playlist.

Estimate review work from uncertainty, not only size

A 400-track playlist with modern releases and strong ISRC coverage may need less human review than a 100-track collection of bootlegs, local files, remixes, and regional releases. The useful estimate comes after matching: Ready rows are largely mechanical, while Review and Missing rows consume attention.

Review in batches. Start with Missing rows because they may require external search or a conscious decision to leave them out. Then inspect Review rows with version words, duration differences, or artist conflicts. You do not need to open every Ready row when a shared recording identifier and metadata agree, but spot-check a few across the playlist.

Use landmarks

Remember the first tracks, a few distinctive songs in the middle, and the final tracks. These landmarks make it faster to verify order in Apple Music after excluded rows close the gaps.

Recover from an interruption without repeating correct work

PlaylistXfer stores an anonymous session identifier and the most recent transfer reference in the browser. The match report and review decisions are saved server-side for that anonymous session so a refresh can restore the latest analysis.

If the page closes after matching, return in the same browser and use the offered saved transfer. If the report is correct, continue reviewing or retry creation. Avoid starting a new analysis only because Apple Music authorization was cancelled or creation returned a temporary error.

Start over when the source link, analysis scope, destination storefront, or match evidence is wrong. Continue the saved report when only the final Apple Music connection needs another attempt.

If the source contains more than 500 transferable rows

The current production web job caps one analysis at 500 rows. Split a larger source into intentional sections inside Spotify, then transfer each section separately. Use names such as “Part 1 — 1 to 500” and “Part 2 — 501 onward” so the destination playlists are easy to verify and merge manually if desired.

Split by meaningful boundaries when possible: year, genre, activity, alphabet, or original disc/era. A semantic split is easier to audit than two arbitrary piles because you can recognize whether a song landed in the expected destination.

Do not assume the Spotify headline count equals transferable rows. Preview first, then decide where to split based on readable music tracks rather than podcasts, local files, or unavailable entries.

Large-playlist transfer checklist

  1. Verify the Spotify URL while signed out.
  2. Use 50 or 150 only for a deliberate dry run.
  3. Run Full playlist for the final transfer, up to 500 rows.
  4. Review Missing first, then version-sensitive Review rows.
  5. Restore a saved report after refresh instead of repeating good analysis.
  6. Reconnect Apple Music only when the report is ready to create.
  7. Compare counts, order landmarks, versions, and playback after creation.
  8. Split sources above 500 rows into clearly named sections.
